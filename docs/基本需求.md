需求

1. 号池路由，允许用户添加不同的 provider和key管理,统一集中管理账号，让调用方只需要添加本项目这一个provider即可使用多方账户模型。
2. 提供基本API支持，包括从服务端获取账户信息和余额，也向客户端提供模型列表等API。
3. 支持 Token 用量查询
4. 支持会话，缓存以及图像输入。
5. 支持多个协议转换，也就是接收三种协议也可以转换成三种协议
6. 支持AI工具包括thinking effort

技术

1. 后端使用 kotlin spring 4.x，JPA + QueryDSL，PostgreSQL，数据库已经建好为router_db，localhost postgres 和 20230612. 注意配置文件用环境变量占位，然后创建一个etc文件夹存放开发和生产的环境，参考blog
2. 前端使用 vite ts react tailwindcss
3. 风格参考 /home/cacc/Repositories/blog
4. 使用我的工件，包括 common 与 security（通过keycloak登录）可以使用maven中仓的版本（两个我都发布了）
5. 网络上要利用好 kotlin 的协程功能

流程

完成后自动提交两次，一次为后端构建完成，第二次为前端构建完成
后端分 common 与 app，common 仅放 request response 相关定义，方便如果后期出现耦合项目直接使用他的common包而不是重复定义 DTO。
前端风格参考 /home/cacc/Repositories/blog/docs/admin-design-system.md
其中项目文件夹中的bifrost和litellm都是现成的参考项目，模型架构与http协议相关的处理可以参考他们
